# MedLM AI permanent development instructions

## Project and current phase

MedLM AI is an India-first, five-platform medication information and management application. Read ARCHITECTURE.md, REQUIREMENTS.md, API_SPEC.md, DATABASE_SCHEMA.md, SECURITY.md, AI_PIPELINE.md and DEVELOPMENT_PLAN.md before relevant changes. Work within that scope without repeatedly asking for approval for routine reversible changes. Do not publish or deploy unless instructed. Inspect git state first and preserve user work. ## Medical safety invariants

- GPT is never authoritative medical evidence. Use approved, versioned sources and field-level provenance. Never invent medicine identity, ingredient, dose, contraindication, interaction or claim.
- Never diagnose, prescribe, recommend stopping a prescription, or alter a doctor's regimen. No missed-dose or organ-function dosing advice generated by the model.
- Keep observed packaging text, user corrections, ingredient-only evidence and verified product identity distinct. India is the launch market; US data cannot by itself verify Indian brands or local prescription status.
- Unsupported, ambiguous, conflicting and stale evidence are explicit states. Abstain rather than choose a plausible answer. Missing interaction evidence never means safe/no interaction.
- Uncertain medicine candidates require explicit, versioned identity review before attachment/use; user selection never substitutes for authoritative source verification. Revalidate prescription-derived clinical fields at every schedule activation, including edits.
- Preserve literal prescription text and nullable fields. Every prescription-derived medication schedule requires authenticated review of the current draft version, enforced server-side. AI output or a client boolean cannot bypass confirmation.
- Keep drug strength separate from prescribed dose. Never infer units, pill counts, frequency intervals or food timing. User reminder preferences are recorded separately from prescribed instructions.
- Source/model/prompt/translation changes require the relevant clinical-safety regression suite. Do not weaken abstention or safety checks merely to make a demo pass.

## Privacy and security invariants

- Treat images, OCR, medicines and dose history as sensitive. No real patient fixtures, raw prompts, images, secrets or identifying medical logs in git, telemetry or screenshots used for documentation.
- Keep API keys and service-role credentials server-side. Use secret management and least privilege; no hardcoded credentials, permissive CORS or public image buckets.
- Follow image lifecycle limits and verify actual deletion. `store:false` is not a claim of provider Zero Data Retention. No medical data sent to unreviewed processors.
- Enforce owner authorization in API, database and storage. Test using real runtime roles; table owners/service roles can bypass RLS. Set user context transaction-locally.
- Treat image/source text as untrusted input. Models cannot execute arbitrary tools, fetch arbitrary URLs, activate reminders or write clinical records.
- Push payloads contain opaque IDs/generic text. Cancellation, logout, account deletion and worker races must prevent new server jobs/reminders; track pending cancellation of already scheduled alerts on disconnected devices rather than claiming an immediate remote wipe.
- Do not claim regulatory/privacy compliance from technology choices. Follow the documented India launch review gate.

## Engineering standards

- Prefer shared Flutter domain/UI code with explicit platform adapters. Test Android, iOS, web, Windows and macOS; do not assume plugin parity. Apple builds require macOS.
- Accessibility outranks decorative neumorphism. Support both themes, readable scalable type, keyboard/focus/semantics, localization and reviewed clinical translations.
- English, Hindi and Telugu are required launch locales. Evaluate OCR/vision and clinical translation independently per language; never assume ML Kit supports Telugu. Keep market policies/provider adapters independent of language and shared client/domain code.
- FastAPI handles clinical domain writes; use typed Pydantic contracts, versioned OpenAPI and generated client bindings. Validate schemas and domain semantics independently.
- PostgreSQL is the source of truth. Use migrations, owner-consistent foreign keys, transactions, outbox, idempotency and optimistic concurrency. Never silently resolve conflicting dose actions by last-write-wins.
- Use immutable prescription confirmations, schedule versions, source/report revisions and append-only dose corrections. Historical doses retain their original schedule context.
- Reminders are best effort; expose capability/permission/sync status. Test timezones, DST, reboot, offline use, duplicate events and cancellation. Never equate notification delivery with medication taken.
- Research current official documentation before relying on evolving APIs or platform rules. Verify model identifiers and real account access; never silently substitute the requested model. Cite source/date in changed architecture decisions.
- Review package maintenance, license, privacy and platform support before adding dependencies. Pin reproducible versions; use a single domain migration authority.
- Run tests appropriate to the changed risk area. Medical, authorization, reminder and deletion changes need meaningful regression tests; report precisely what passed and what could not run.
- Use synthetic data for examples and initial API calls. Follow minimal patches, avoid unrelated refactors, and keep implementation status honest.
- Update design documents when contracts or invariants change, with rationale and implications. Record significant decisions in docs/adr once that directory is created.
- Do not introduce autonomous multi-agent workflows or delegate work unless the user or an applicable task instruction explicitly requests it.

## Completion reporting

State what changed, why, validation performed and remaining blockers. Never describe a planned component as implemented, an API as tested without a call, or a medical capability as validated without release evidence. Stop after the authorized phase.
